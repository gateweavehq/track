# MCP reference

Track is an [MCP](https://modelcontextprotocol.io) server. An agent connects to `/mcp`, works
with the permissions of whoever it signs in as, and everyone sees its edits live, as they would
anyone else's. This page says how to connect and lists every tool the server offers.

## How to connect

### The MCP URL

- **Gateweave Cloud:** `https://track.gateweave.com/mcp`
- **A self-hosted copy:** `<BETTER_AUTH_URL>/mcp`, for example `https://track.example.com/mcp`.
  Tokens are bound to one address, so the endpoint is only on once `BETTER_AUTH_URL` names it
  (see [self-hosting](self-hosting.md#ai-agents-mcp)). Locally, set it to `http://localhost:4710`
  in `.dev.vars` and connect to `http://localhost:4710/mcp`.

### How a client signs in

- **OAuth with the `track` scope.** The client sends you to Track to sign in and approve it, and
  then acts with your permissions. In Claude Code, run `/mcp` to sign in.
- **An agent key.** An agent that works on its own, such as a triage bot, should not act as you.
  An admin creates an agent member for it under Settings, Agents. It joins the workspace under
  its own name, can do what members do except create or change projects (that takes a person), and
  connects with the key shown there as `Authorization: Bearer <key>`, with nothing else to set up.

### Client setup

With Claude Code and Gateweave Cloud, signing in with OAuth:

```sh
claude mcp add --transport http gateweave-track https://track.gateweave.com/mcp
```

With an agent key:

```sh
claude mcp add --transport http track https://track.gateweave.com/mcp \
  --header "Authorization: Bearer gwt_..."
```

Other MCP clients take the same URL. A generic JSON config for a client that reads one (the
field names differ a little from client to client):

```json
{
	"mcpServers": {
		"track": {
			"type": "http",
			"url": "https://track.gateweave.com/mcp",
			"headers": { "Authorization": "Bearer gwt_..." }
		}
	}
}
```

Leave `headers` out to sign in with OAuth instead.

## Tools

Every tool needs the `track` scope. In the table, a `?` marks an input the call may leave out,
and the output column lists the top-level fields of the tool's output schema. Where an admin set
an agent member to propose some kinds of change, each configured change to an issue is not made:
it comes back under `proposed`, for a person to accept or dismiss. Track decides each change on
its own, so the other fields of the same call can still be applied.

The table is generated from the server's own `tools/list`, not typed by hand. After changing a
tool, rewrite it with `pnpm docs:mcp`; a test fails while it is out of date. What each tool needs
comes from `TOOL_NEEDS` in `apps/web/src/server/mcp/reference.ts`.
